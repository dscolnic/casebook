# RECKON — New Game Ideas

Candidate games beyond the current six (Casebook, Diagnosis, Sequence, Ballpark,
Science Tank, Protocol). Each targets a *different* cognitive skill than the existing
games, keeps the RECKON DNA (one defensible answer, deducible from what's shown, no
trivia/luck, education is load-bearing), and fits the same self-contained daily-puzzle
format. ⭐ = top picks / most ONR-relevant.

## Skill coverage today
Deduction (Casebook) · consistency-checking (Diagnosis) · ordering (Sequence) ·
estimation (Ballpark) · judgment under hidden info (Science Tank) · tool-matching
(Protocol). **Gaps:** prediction, critical appraisal, spatial/localization,
constrained design, nonlinearity, decoding.

---

## ⭐ Peer Review — *find the fatal flaw*
A study is presented with a confident conclusion; the player triages a set of review
notes into **Fatal flaw / Valid concern / Not a problem** — exactly one note is fatal.
- **Teaches:** critical appraisal — the crucial lesson that *every study has
  limitations, but only some invalidate the conclusion.*
- **Distinct because:** it's meta-science (reasoning about evidence itself), which no
  other game touches. Arguably the highest-value literacy skill in the suite.
- *(Charted out in full in `PEER_REVIEW_SPEC.md`.)*

## ⭐ Consequence — *predict the outcome*
Show a real system plus one change to it; the player picks which of four outcome
curves/results actually happens.
- **Teaches:** mechanistic prediction — reasoning *forward* from rules into an unknown.
- **Distinct because:** it's the inverse of Sequence (predict an unknown outcome vs.
  order known steps). Naturally visual: pick-the-graph.
- **Example:** "Upstream forest is cleared — which downstream flood-peak curve results?"

## ⭐ Fix — *triangulate the source*
Given several sensor readings on a map (bearings, time-differences, signal strengths),
pinpoint where the source is.
- **Teaches:** geometry, multilateration, sensor fusion.
- **Distinct because:** it's spatial and interactive (drag a pin) — nothing else in the
  suite is. Strongly naval (sonar, RF direction-finding, GPS).
- **Example:** "Three hydrophones hear a contact at these arrival times — mark it."

## Payload — *design under constraints*
Build a mission or device by spending a fixed budget (mass / power / money / time)
across parts to meet a hard requirement; the reveal says whether the design works.
- **Teaches:** engineering trade-offs and requirement satisfaction.
- **Distinct because:** it's *does it work* (meet spec), not *did it pay off* (Science
  Tank's investment return).
- **Example:** "Reach orbit within this mass budget" / "meet the sensor spec on this power budget."

## Tipping Point — *find the critical threshold*
Determine the value at which a system flips behavior — buckling load, escape velocity,
R₀ = 1, laminar→turbulent, critical mass — and what happens on each side.
- **Teaches:** nonlinearity and critical phenomena.
- **Distinct because:** no current game isolates thresholds/tipping behavior.

## Rosetta — *decode the representation*
Turn one representation into its meaning: a spectrum → the molecule, a waveform → the
message, a light-curve → the planet, coordinates between reference frames.
- **Teaches:** reading signals as meaning; pattern-to-inference.
- **Distinct because:** it's about translation/decoding, not deduction or estimation.

---

## Build order suggestion
Start with **Peer Review** or **Consequence** — both are mechanically fresh, high on
educational value, and buildable with the existing daily/stats/hub scaffolding. **Fix**
is the most novel interaction (a real map) but a bit more work to build well.
